# YOLOVAIM

基于用户自备 YOLO 模型的 Android 屏幕目标检测 + 触控自动化框架。

**不内置任何模型，也不针对任何特定应用。** 检测什么、瞄准什么，完全取决于你自己
导入的模型和你自己填写的类别。就像 GG 修改器本身不针对任何游戏一样，这个项目
提供的是通用的「屏幕推理 → 覆盖层显示 → 触控注入」管线。

---

## 设备要求

| 项目 | 要求 |
|------|------|
| 芯片 | 骁龙 8 Gen 1 及以上（SM8450+）可用 QNN HTP 加速；其他芯片走 GPU / CPU 回退 |
| 系统 | Android 12 (API 31) 及以上 |
| 架构 | arm64-v8a |

推理后端会自动按 QNN HTP → GPU → CPU 顺序回退，低端芯片能跑但速度会明显下降。

---

## 前置准备：Shizuku

本应用依赖 Shizuku 进行触控注入（或者 Root，见下）。

1. 安装 [Shizuku](https://shizuku.rikka.app/)
2. 打开 Shizuku，选择 **通过无线调试启动**，按指引完成配对
3. Shizuku → **管理已授权应用** → 找到本应用并开启授权

有 Root 的设备会优先走 Root 通道（`su` + `root_daemon`），Shizuku 作为回退。

## 触摸方式（三选一，主界面下拉切换）

| 方式 | 要求 | 说明 |
|------|------|------|
| Uinput | Root（回退 Shizuku） | 虚拟输入设备注入，默认 |
| InputManager | Shizuku | 适配面最广 |
| **Stealth（无痕）** | Root + 内核 KPM | 报文经内核 `input_event` 直达真实触摸屏设备：不产生新输入节点、设备数量不变、免疫驱动「补刀」；防录屏 HUD 照常可用 |

### Stealth 无痕方式的额外准备

1. **内核装 KPM**：APatch 管理器 → KPM → 安装 `inputprobe.kpm`（KernelSU/Magisk 先刷 KPatch-Next-Module）。模块来自[无痕触摸库项目]，或自行用 kpm-src 源码构建。
2. **配对**：通道只认用「相同包名 + 盐」编译出的 app 与 KPM。盐直接写在源码里（`touch_pairing.h` 的 `TOUCH_PAIR_SALT`，见该文件头注释的决策说明）——**构建零配置**，任何人克隆源码构建出的 app 都能与同盐编译的 `inputprobe.kpm` 直接配对。换盐 = 同时改两侧头文件（`scripts/sync_touch_pairing.sh` 负责同步）后各自重编。
3. Stealth 失败**不降级**：内核没装 KPM 或盐不一致时，状态栏会显示人话原因，不会静默换有痕注入。

## 导入模型

应用第一次启动时模型列表是空的，需要你自己导入。

### 支持的格式

| 格式 | 需要选中的文件 |
|------|----------------|
| TFLite | `.tflite` 单个文件 |
| NCNN | `.param` 和 `.bin` 两个文件（同时选中，或分两次导入，同名即可配对） |

### 步骤

1. 主界面 → **导入模型** → 在文件选择器里选中模型文件
2. 导入时会自动解析模型的张量形状，填好输入尺寸、输入类型、输出数量和类别数量
3. 弹出的信息框里确认或改写：
   - **显示名称** —— 列表里怎么显示
   - **输入尺寸** —— 正方形边长；TFLite 一般不用改，NCNN 可能需要手填
   - **输出数量** —— anchor 数量，填 0 表示交给引擎自己从模型读
   - **类别名** —— 按 class id 顺序、逗号分隔，例如 `target, head`

类别名默认是 `class_0` / `class_1` …，因为类别的语义完全取决于你训练时用的数据集，
应用不做任何猜测。填成有意义的名字之后，控制面板里的按类别开关、按类别偏移才好认。

模型文件被复制到应用私有目录 `filesDir/models/`，元数据记在同目录的
`registry.json`。在应用内删除模型会连带删掉文件本身。

### 自己训练并导出

```python
from ultralytics import YOLO
model = YOLO('best.pt')
model.export(format='tflite', int8=True, data='your_dataset.yaml')
```

导出的 `best_saved_model/best_full_integer_quant.tflite` 直接导入即可。

输出张量应为 `[1, 4+nc, num_anchors]`：前 4 通道是 cx / cy / w / h（归一化到 [0,1]），
其后每个通道对应一个类别的分数。

## 使用

### 启动

1. 首次运行授予 **屏幕录制** 和 **悬浮窗** 权限
2. 选好模型，点 **启动**
3. 悬浮球出现后切到目标应用

### 悬浮球

- 拖动可移动位置
- 点击打开 / 关闭控制面板
- 长按停止服务

### 控制面板

| 标签 | 功能 |
|------|------|
| 自瞄 | 自动瞄准开关、PID 参数（响应速度 / 平滑度）、贝塞尔曲线模式 |
| 扳机 | 自动触发开关、反应延迟、冷却时间 |
| 防闪 | 目标锁定、抖动模拟 |
| 模型 | 切换已导入的模型 |
| 系统 | 置信度阈值、覆盖层显示、CPU 推理开关 |

### 功能

**自动瞄准** —— 检测到目标后通过 PID 控制器或贝塞尔曲线把虚拟手指平滑移向目标，
不会瞬移。Kp 越大响应越快，Kd 越大越平滑。

**自动触发** —— 准心与检测框重合时自动点击。

**按住触发（Hold-to-Fire）** —— 需要物理手指按在触发区内自瞄才激活，松手即停。

**覆盖层** —— 屏幕上画出检测框，绿色高置信度、黄色低置信度，可在设置里关闭。

**区域设置** —— 四个可配置区域：触发区、按住区、瞄准起点区、摇杆区。

## 常见问题

**导入模型后加载失败**
检查是不是 YOLO 导出的 tflite / ncnn。输出张量形状不是 `[1, 4+nc, N]` 的模型
（比如带 NMS 的 `_saved_model` 导出、或 SSD / EfficientDet）当前不支持。

**NCNN 模型报「缺少同名 .bin」**
`.param` 只是网络结构，权重在 `.bin` 里。两个文件都要导入，且主文件名必须一致。

**类别开关里显示 class_0 / class_1**
说明还没改类别名。主界面 → 编辑信息 → 类别名。

**首次选中某个模型时卡几秒**
QNN 在编译 HTP 图。编译产物会缓存到 `cache/qnn/`，之后切换就快了。应用启动时
会后台预热所有已导入的 tflite 模型。

**推理速度慢**
可能回退到 CPU 了。控制面板 → 系统 里能看到当前后端。

**检测框不出现**
确认屏幕录制权限已授予、Shizuku 在运行且已授权本应用、置信度阈值别调太高。
